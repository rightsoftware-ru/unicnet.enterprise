# Установка UnicNet

Эта инструкция поможет установить UnicNet с нуля и выполнить первый вход. Все необходимые службы, включая PostgreSQL и Keycloak (систему учётных записей), запускаются автоматически через Docker Compose.

Для обновления уже работающего UnicNet эта инструкция не подходит. Не распаковывайте новую поставку поверх настроенной папки.

## 1. Что понадобится

- Компьютер или сервер Linux x86-64 либо Windows x64 с установленным Docker Desktop в режиме **Linux containers**.
- Docker Compose версии 2 или новее. На Linux Docker должен быть запущен, а ваша учётная запись должна иметь доступ к нему.
- Доступ к хранилищу образов `cr.yandex` и реквизиты для входа, полученные у поставщика или администратора.
- Действующий файл лицензии `license.txt`.
- Адрес сервера и сеть устройств, с которыми будет работать UnicNet. Если вы их не знаете, уточните у вашего администратора.

Python и сборка программ для установки не требуются.

Откройте PowerShell на Windows или терминал на Linux и выполните:

```sh
docker version
docker compose version
```

Первая команда должна показать сведения и о Client, и о Server. Вторая — версию Compose. Если команда не найдена или Docker не отвечает, сначала настройте Docker с помощью администратора. На Windows проверьте, что Docker Desktop запущен.

## 2. Откройте папку поставки

Получите актуальную поставку у поставщика и распакуйте её **в новую папку**. Если используете репозиторий, откройте его корневую папку. В ней должны лежать `compose.yml`, `.env.example` и `infrastructure.example.json`.

Все дальнейшие команды выполняйте **из этой папки**:

- Windows: откройте папку в Проводнике и выберите «Открыть в терминале» → PowerShell.
- Linux: откройте терминал и перейдите в папку командой `cd /путь/к/папке`. Замените путь на свой.

Убедитесь, что видите `compose.yml`: выполните `dir` на Windows или `ls` на Linux. В обновлённом репозитории не нужно переходить в подпапку `unicnet-docker`.

## 3. Подготовьте настройки и лицензию

Если файлы `.env`, `infrastructure.json` и `frontend-settings.json` уже есть в новой поставке, оставьте их. Следующие команды создадут только отсутствующие файлы.

**Windows — PowerShell:**

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
if (!(Test-Path infrastructure.json)) { Copy-Item infrastructure.example.json infrastructure.json }
if (!(Test-Path frontend-settings.json)) { Copy-Item frontend-settings.example.json frontend-settings.json }
notepad .env
```

**Linux:**

```sh
test -e .env || cp .env.example .env
test -e infrastructure.json || cp infrastructure.example.json infrastructure.json
test -e frontend-settings.json || cp frontend-settings.example.json frontend-settings.json
nano .env
```

На Linux можно использовать другой текстовый редактор вместо `nano`. В `.env` измените две строки:

```dotenv
UNICNET_HOST=198.51.100.10
UNICNET_CIDR=198.51.100.10/24
```

Это примеры — **подставьте свои значения**:

- `UNICNET_HOST` — IP-адрес или DNS-имя сервера UnicNet, без `http://`, пути и порта. Именно этот адрес пользователи будут открывать в браузере. `localhost` подходит только для работы с того же компьютера.
- `UNICNET_CIDR` — сеть устройств для работы UnicNet. Она может отличаться от сети самого сервера. Значение в примере означает сеть `198.51.100.10` с маской `255.255.255.0`.

Сохраните файл. Остальные строки `.env` для обычной установки оставьте без изменений.

Скопируйте полученный **`license.txt` в ту же папку, где находится `compose.yml`**. Файл должен содержать одну строку лицензии без кавычек. На Windows включите отображение расширений файлов и убедитесь, что имя не получилось `license.txt.txt`.

Пароли служб вручную задавать не нужно: они создадутся автоматически. Пустой `frontend-settings.json` также заполнится автоматически.

**Если PostgreSQL или Keycloak у вас уже установлены:** до первого запуска выполните [инструкцию подключения существующих служб](docs/EXTERNAL-SERVICES.md), затем вернитесь к шагу 4. Для обычной установки менять `infrastructure.json` не нужно.

## 4. Скачайте и запустите UnicNet

Команды одинаковы для PowerShell и Linux. Выполняйте их по очереди; если команда завершилась ошибкой, сначала устраните её.

Войдите в хранилище образов:

```sh
docker login cr.yandex
```

Используйте реквизиты, выданные поставщиком или администратором. Пароль или токен вводите только в запросе терминала; в чат его отправлять не нужно. Успешный вход сопровождается сообщением `Login Succeeded`.

Проверьте настройки:

```sh
docker compose config --quiet
```

Если ошибок нет, команда завершится без вывода. Затем скачайте образы и запустите службы:

```sh
docker compose pull
docker compose up -d
```

Загрузка и первый запуск могут занять несколько минут. Возврат командной строки ещё не означает, что установка завершилась: выполните следующую проверку.

## 5. Убедитесь, что установка завершена

```sh
docker compose ps -a
docker compose logs --tail 20 verify
```

Установка успешна, когда одновременно выполнены три условия:

1. У `prepare`, `database`, `init`, `verify` статус **`Exited (0)`**. Это задания подготовки; их остановка с кодом 0 — нормальный результат.
2. Остальные **восемь служб** имеют статус **`Up … (healthy)`**. При подключении одной внешней службы таких контейнеров будет семь, при двух — шесть.
3. В логах `verify` есть строка:

```text
UnicNet готов: HTTP, первый вход и закрытый bootstrap проверены.
```

Если видите `Created`, `health: starting` или работающий `verify`, подождите и повторите эти две команды. `Exited (1)` и другие ненулевые коды, `unhealthy` или постоянные перезапуски означают ошибку — перейдите к разделу 7.

На Linux дополнительно можно выполнить `sh accept-deployment.sh`: эта команда проверит перечисленные условия автоматически. Использовать `docker compose wait verify` не нужно.

## 6. Получите пароль и войдите

После успешной проверки сохраните файл с реквизитами рядом с `compose.yml`:

```sh
docker compose cp prepare:/state/initial-admin.json ./initial-admin.json
```

Откройте `initial-admin.json` текстовым редактором на своём компьютере или сервере. В стандартной установке имя пользователя — **`admin`**, пароль сгенерирован автоматически и указан в файле. Не отправляйте этот файл в чат или заявку поддержки.

Откройте в браузере, заменив `АДРЕС` на значение `UNICNET_HOST`:

- **UnicNet:** `http://АДРЕС:8080` — основной интерфейс приложения.
- **Keycloak:** `http://АДРЕС:8095/admin/master/console/` — управление учётными записями.

Например, при `UNICNET_HOST=198.51.100.10` адрес приложения — `http://198.51.100.10:8080`.

Начальные реквизиты одинаковы для двух отдельных учётных записей UnicNet и Keycloak. Смена пароля одной записи не изменит пароль другой. При внешнем Keycloak используйте его адрес и выбранный realm; для готового realm реквизиты проверочного пользователя задаёт ваш администратор.

Создайте персональных администраторов и проверьте их вход **до отключения начальных учётных записей**. Для администратора UnicNet достаточно добавить пользователя в подготовленную группу `Administrators`. Пошаговые пояснения и права: [первый вход и настройка пользователей](docs/README-FIRST-RUN.md).

Служебную учётную запись **`unicnet-service` не удаляйте**: она нужна приложениям.

## 7. Если что-то не получилось

- **`401 Unauthorized` при скачивании:** повторите `docker login cr.yandex` под той же учётной записью ОС. Если ошибка осталась, попросите администратора проверить права доступа к образам.
- **`Permission denied` при обращении к Docker на Linux:** попросите администратора предоставить вашей учётной записи доступ к Docker.
- **Не найден файл лицензии или настроек:** проверьте, что вы в папке с `compose.yml` и выполнили шаг 3.
- **Порт уже занят (`port is already allocated` / `address already in use`):** на сервере уже работает другая служба с таким портом. Согласуйте с администратором освобождение порта; не останавливайте чужие службы самостоятельно.
- **Приложение не открывается с другого компьютера:** проверьте `UNICNET_HOST`, доступность сервера по сети и разрешение TCP-порта 8080 в межсетевом экране. Для консоли Keycloak нужен также TCP-порт 8095.
- **Служба завершилась с ошибкой или стала `unhealthy`:** посмотрите состояние и последние сообщения:

```sh
docker compose ps -a
docker compose logs --tail 100 prepare database vault init verify
```

Если Keycloak запускается этой поставкой, дополнительно выполните:

```sh
docker compose logs --tail 100 keycloak
```

После устранения причины повторите:

```sh
docker compose up -d
```

Затем снова выполните проверку из шага 5. Созданные пароли и данные при повторном запуске сохраняются.

Для обращения в поддержку подготовьте текст ошибки и состояния контейнеров. Перед передачей логов удалите пароли, токены, лицензию и персональные данные. Файлы `license.txt`, `initial-admin.json`, `.env` и `infrastructure.json` не прикладывайте.

## 8. Как остановить и снова запустить

Остановить службы с сохранением данных:

```sh
docker compose stop
```

Запустить снова из той же папки:

```sh
docker compose up -d
```

Данные хранятся в Docker volumes (отдельных хранилищах Docker) и `frontend-settings.json`. **Не выполняйте `docker compose down -v` и не удаляйте volumes: это удалит данные.** Сохраните папку установки и не меняйте имя проекта, режимы служб и параметры уже настроенного стенда без согласованной процедуры.

Автоматическое обновление и резервное копирование пока не входят в эту поставку. Для обновления, смены лицензии или переноса рабочего стенда обратитесь к поставщику.
