# Установка UnicNet на Linux

Руководство предназначено системному администратору организации, которая впервые развёртывает UnicNet. Оно описывает установку на одном Linux-сервере с возможностью подключения существующих PostgreSQL и Keycloak. Знакомство с внутренней инфраструктурой поставщика не требуется.

UnicNet устанавливается готовыми Docker-образами. Выберите один из четырёх вариантов, заполните настройки и выполните одинаковые команды запуска. Python, .NET и сборка образов на сервере не нужны.

**Без действующей лицензии UnicNet работать не будет. Скачивание образов с помощью токена не заменяет лицензию.**

<a id="requirements"></a>
## 1. Что подготовить

- Сервер Linux x86-64 с Docker Engine 24 или новее и плагином Docker Compose v2 или новее (`docker compose`). Ваша учётная запись должна иметь доступ к Docker. Установка Docker выполняется по [официальной инструкции для вашего дистрибутива](https://docs.docker.com/engine/install/).
- Сетевой доступ к `cr.yandex`. Токен для скачивания образов находится в файле `registry-token.txt`, включённом в поставку; имя пользователя — `oauth`.
- **Действующий файл `license.txt` с одной строкой лицензии без кавычек. Его выдаёт поставщик отдельно.**
- Адрес сервера и сеть устройств, с которыми будет работать UnicNet.
- Согласованные [сетевые доступы](docs/OPERATIONS.md#network) и свободные порты служб.
- Дисковое пространство для образов, базы и журналов. Требуемые CPU, RAM и объём диска согласуйте с поставщиком по числу устройств, нагрузке и сроку хранения журналов; проверенный минимум для промышленной нагрузки в поставке не указан.

<a id="server"></a>
### Операционная система и ресурсы

Базовые ОС из требований продукта — Ubuntu 22.04 и 24.04 LTS. Текущая Compose-поставка проверена на Ubuntu 24.04.2 LTS с Docker Engine 29.8.0 и Docker Compose 5.5.1. Ubuntu 22.04 и другие версии Docker отдельно в этой приёмке не проверялись.

Четыре варианта первоначальной установки и вход администратора проверены последовательно на окружении с 1 vCPU, примерно 2 ГиБ RAM, 2 ГиБ swap и диском 48 ГиБ. Это описание условий проверки без нагрузочного испытания, а не рекомендуемый размер клиентского сервера и не гарантия работы с заданным числом устройств.

До выделения сервера согласуйте с поставщиком число устройств, протоколы и периодичность опроса, объём Syslog и срок хранения, число пользователей и размещение PostgreSQL/Keycloak. По этим данным поставщик определяет CPU, RAM и диск. Утверждённые числовые требования для пилотной нагрузки в репозитории не опубликованы.

Проверьте Docker в терминале сервера:

```sh
docker version
docker compose version
```

Первая команда должна показывать Client и Server, вторая — версию Compose. Если Docker недоступен, обратитесь к администратору.

<a id="get-release"></a>
### Получение поставки

Получите файлы установки из репозитория. Токен скачивания находится в `registry-token.txt`. **Файл `license.txt` необходимо получить у поставщика отдельно: без действующей лицензии UnicNet работать не будет.**

Если получен архив, распакуйте его в **новую папку**, сохранив вложенные каталоги, и найдите в ней `compose.yml`.

Для получения файлов через Git выполните:

```sh
git clone https://github.com/rightsoftware-ru/unicnet.enterprise.git
cd unicnet.enterprise
```

Git нужен только при таком способе получения файлов; для установки из архива он не требуется. Для скачивания закрытого репозитория используйте свою учётную запись с предоставленным доступом.

Откройте терминал в папке с `compose.yml`. Все дальнейшие команды выполняются из неё. Эта инструкция предназначена для первоначальной установки; не применяйте её поверх работающего стенда и не распаковывайте новый архив поверх его настроек.

<a id="variants"></a>
## 2. Выбрать вариант установки

Выберите **ровно один** вариант и выполните его две команды. Они создают `.env` и `infrastructure.json`. Для уже настроенного стенда повторно копировать эти файлы не нужно.

<a id="all-local"></a>
### Вариант 1. Всё установить вместе с UnicNet

PostgreSQL и Keycloak запустятся автоматически на этом же сервере. Выбирайте этот вариант, если у вас нет существующих служб.

```sh
cp .env.example .env
cp infrastructure.example.json infrastructure.json
```

<a id="external-postgres"></a>
### Вариант 2. Использовать существующий PostgreSQL

PostgreSQL уже подготовлен вашим администратором; Keycloak установится вместе с UnicNet.

```sh
cp examples/external-postgres.env .env
cp examples/external-postgres.json infrastructure.json
```

<a id="external-keycloak"></a>
### Вариант 3. Использовать существующий Keycloak

Keycloak уже подготовлен вашим администратором; PostgreSQL установится вместе с UnicNet.

```sh
cp examples/external-keycloak.env .env
cp examples/external-keycloak.json infrastructure.json
```

<a id="external-both"></a>
### Вариант 4. Использовать обе существующие службы

PostgreSQL и Keycloak уже доступны. Состав UnicNet запустится без локальных контейнеров этих двух служб.

```sh
cp examples/external-both.env .env
cp examples/external-both.json infrastructure.json
```

<a id="settings"></a>
## 3. Заполнить настройки

Откройте `.env` текстовым редактором, например `nano .env`. Измените две строки:

```dotenv
UNICNET_HOST=un.example.org
UNICNET_CIDR=198.51.100.0/24
```

**Подставьте свои значения.** `UNICNET_HOST` — DNS-имя или IP-адрес вашего сервера без протокола и порта. `UNICNET_CIDR` — сеть устройств для работы UnicNet; она может отличаться от сети самого сервера. Приведённые адреса зарезервированы для документации и не являются настройками рабочего сервера. Если значения неизвестны, уточните их у администратора.

Другие строки `.env` уже выбраны для вашего варианта. Менять состав Compose-файлов вручную не требуется. Строка `COMPOSE_FILE` выбирает службы, `COMPOSE_PATH_SEPARATOR=|` задаёт разделитель имён файлов; сохраните её.

Встроенные службы имеют версии PostgreSQL 18 и Keycloak 26.7.0, приложения и инициализатор — `rc-init-test`. Это предварительная версия поставки. Не заменяйте теги на `latest` и не меняйте версии при повторном запуске настроенного стенда.

Для вариантов 2–4 откройте `infrastructure.json` и замените значения примера реквизитами внешних служб. Порядок подготовки базы, права и варианты realm описаны в [подключении внешних служб](docs/EXTERNAL-SERVICES.md). Пароли вводите только в локальный файл на сервере.

Скопируйте `license.txt` в папку с `compose.yml`. Создайте файл настроек интерфейса, если его ещё нет:

```sh
test -e frontend-settings.json || cp frontend-settings.example.json frontend-settings.json
chmod 600 .env infrastructure.json license.txt
```

Пароли встроенных служб и ключи будут созданы автоматически. Не редактируйте `frontend-settings.json`: его заполнит приложение.

<a id="start"></a>
## 4. Скачать и запустить

Команды одинаковы для всех четырёх вариантов. Выполняйте их по очереди. При ошибке сначала устраните её.

```sh
chmod 600 registry-token.txt
docker login --username oauth --password-stdin cr.yandex < registry-token.txt
docker compose config --quiet
docker compose pull
docker compose up -d
```

Настройки `.env`, `infrastructure.json`, `frontend-settings.json` и `license.txt` должны находиться рядом с `compose.yml`; они не входят в Git.

Команда входа читает токен из `registry-token.txt`; вводить его в командную строку не требуется. Успешный вход сопровождается `Login Succeeded`. Docker сохраняет данные входа в настроенном хранилище учётной записи ОС; исходный файл нужен для повторного входа и замены токена. Использование `--password-stdin` описано в [документации Docker](https://docs.docker.com/reference/cli/docker/login/#provide-a-password-using-stdin-password-stdin).

Если поставщик заменил токен, получите актуальный `registry-token.txt` и повторите команду входа перед `docker compose pull`. Compose-файлы и `infrastructure.json` для этого менять не нужно. Проверка `config --quiet` при успехе ничего не выводит. Скачивание и первый запуск могут занять несколько минут.

<a id="login"></a>
## 5. Проверить результат и войти

```sh
docker compose ps -a
docker compose logs --tail 20 verify
```

Успех означает одновременное выполнение всех условий:

- Задания `prepare`, `database`, `init`, `verify` завершились со статусом **Exited (0)**. Их остановка с кодом 0 — нормальный результат.
- Остальные службы работают со статусом **healthy**: восемь служб для варианта 1, семь для вариантов 2 и 3, шесть для варианта 4.
- В логах `verify` есть сообщение:

```text
UnicNet готов: HTTP, первый вход и закрытый bootstrap проверены.
```

При `Created` или `health: starting` подождите и повторите проверку. `unhealthy`, перезапуски и ненулевые коды завершения означают ошибку. Команда `docker compose wait verify` здесь не используется.

Получите реквизиты первого входа:

```sh
docker compose cp prepare:/state/initial-admin.json ./initial-admin.json
chmod 600 initial-admin.json
```

Откройте файл текстовым редактором на сервере. В стандартной установке начальный пользователь — `admin`, случайный пароль указан в файле. Откройте в браузере:

- UnicNet: `http://ВАШ_АДРЕС:8080`.
- Встроенный Keycloak: `http://ВАШ_АДРЕС:8095/admin/master/console/`.

Используйте адрес, указанный в `UNICNET_HOST`. Для внешнего Keycloak используйте его существующий URL. В режиме готового realm для UnicNet используются реквизиты проверочного пользователя, предоставленные администратором.

Начальные admin UnicNet и встроенного Keycloak — две отдельные записи с одинаковым начальным паролем. Создайте персональных администраторов и проверьте их вход перед отключением начальных записей. Для администратора UnicNet назначьте подготовленную группу `Administrators`. [Подробности о правах пользователей](docs/README-FIRST-RUN.md).

**Не удаляйте `unicnet-service`: эта служебная запись используется приложениями.** Реквизиты и лицензию в поддержку не отправляйте.

После проверки входа перейдите к [созданию персонального администратора](docs/README-FIRST-RUN.md#personal-admin) и [подключению первого устройства](docs/README-FIRST-RUN.md#first-device). Готовность контейнеров подтверждает установку, а успешный опрос устройства и получение его событий подтверждают настройку доступа к вашей сети.

<a id="restart"></a>
## 6. Остановка и повторный запуск

Остановить службы с сохранением данных:

```sh
docker compose stop
```

Запустить снова из той же папки:

```sh
docker compose up -d
```

Повторный запуск сохраняет данные и созданные пароли. Данные находятся в Docker volumes и `frontend-settings.json`. **Не выполняйте `docker compose down -v` и не удаляйте volumes: это удалит данные.** Не меняйте имя проекта, базу, realm и вариант установки у настроенного стенда. Автоматическое обновление, перенос и резервное копирование требуют отдельной процедуры поставщика.

<a id="errors"></a>
## 7. Что делать при ошибке

- **401 Unauthorized:** получите актуальный `registry-token.txt` и повторите `docker login --username oauth --password-stdin cr.yandex < registry-token.txt` под той же учётной записью ОС; поставщик должен проверить срок действия токена и права скачивания образов.
- **Permission denied при обращении к Docker:** попросите администратора предоставить доступ к Docker.
- **Не найден файл:** проверьте, что вы в папке с `compose.yml`, и выполнили подготовку настроек и лицензии.
- **Порт уже занят:** согласуйте освобождение порта с администратором.
- **Ошибка подключения к внешнему PostgreSQL или Keycloak:** попросите администратора внешней службы проверить её работу, постоянный адрес и порт, сетевой доступ, TLS и права учётной записи. Если после перезапуска изменился опубликованный порт, восстановите прежнюю точку подключения. После успешной инициализации не подменяйте адрес в `infrastructure.json` как способ переноса: рабочие настройки уже сохранены, перенос требует отдельной процедуры поставщика.
- **Нет доступа из браузера:** проверьте адрес и доступность TCP-порта 8080; для встроенной консоли Keycloak также нужен 8095.

Состояние и сообщения об ошибках:

```sh
docker compose ps -a
docker compose logs --tail 100 prepare database vault init verify
```

Для встроенного Keycloak дополнительно: `docker compose logs --tail 100 keycloak`.

После исправления причины повторите `docker compose up -d` и проверку из шага 5. Перед отправкой логов в поддержку удалите секреты и персональные данные. Не прикладывайте `license.txt`, `initial-admin.json`, `.env` и `infrastructure.json`.
